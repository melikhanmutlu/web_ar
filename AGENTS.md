# ARVision Agent Guidance

## Project

ARVision is a Flask SaaS for converting, optimizing, hosting, sharing and
publishing 3D models to web viewers and mobile AR.

This system improves and sells the existing ARVision product. Do not generate

## Evidence rules

- Verify changing market, company and platform facts with current web sources.
- Prefer official company, platform and standards sources.
- Separate evidence from inference.
- Every target account needs a source URL and verification date.
- Never invent a company, person, title, email address, quote or buying intent.
- Do not infer personal email patterns.
- Do not send email, LinkedIn messages or contact forms without explicit user
  approval.

## Product decisions

- Verify existing capabilities in code, routes, services and tests before
  proposing a feature.
- Tie every feature to a sales blocker, target account, two-week MVP and metric.
- Use `format/kriterler.md` for feature and account scoring.
- Shopify-native functionality is not differentiation by itself.
- Prefer catalog onboarding, SKU mapping, batch QA, cross-platform publishing
  and attribution when supported by customer evidence.

## Code changes

- Preserve unrelated user changes.
- Keep changes scoped to the selected feature.
- Run focused tests, then broader checks when shared behavior changes.
- Do not commit, push, open issues or contact external parties unless the task
  explicitly asks for it.
