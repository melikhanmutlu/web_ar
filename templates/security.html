Security & data practices

You're uploading work that matters. Here's how ARVision keeps it private and under your control.

Your models are private by default

New uploads are unlisted or private — never publicly listed unless you explicitly choose to. Access to a model is governed by a single policy layer: ownership, organization membership, or an active (non-revoked, non-expired) share link.

Access control

Organizations use owner / admin / editor / viewer roles. Share links can be password-protected and time-limited, and revoked at any time. Embeds can be restricted to an allowlist of domains.

Account security

Passwords are stored only as salted hashes, never in plain text. Repeated failed logins lock an account temporarily to blunt brute-force attempts. All state-changing requests are CSRF-protected, and sensitive endpoints are rate-limited.

Data storage

Your files are stored on persistent, access-controlled storage and served over HTTPS. Deleting a model moves it to a recoverable trash and then purges the underlying files from disk on cleanup.

Uploads are handled safely

Converters treat every uploaded file as untrusted: file references inside a model are sanitized, and absolute or parent-directory paths are never honored. Conversion runs in isolated background workers, not in the request path.

Payments

Card data never touches our servers. Checkout runs on the payment provider's hosted page (PayTR, or Lemon Squeezy as Merchant of Record for global cards), and provider callbacks are cryptographically signature-verified.
